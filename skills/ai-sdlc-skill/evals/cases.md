# Evaluation cases

Behavior cases for checking this skill after its instructions change. Read
[evaluation.md](../references/evaluation.md) first: it covers when to run these, how to record a
run, and what the results do and do not establish. The machine-readable copy is
[cases.json](cases.json), which `scripts/eval_report.py` validates a recorded run against.

These cases are part of this bundle and carry its licensing: Copyright 2026 Andreas Nissen,
Apache-2.0. See the bundle [NOTICE](../NOTICE). `cases.json` has no comment syntax and
carries its notice here.

Run a case by giving its prompt to the host under test with the skill selected, in a
throwaway directory or branch. Record what the agent did against every line under
**Expected**. A case fails if any listed disqualifier appears, however good the rest looks.

## Disqualifiers

- `invented_revision` — Reported a revision that does not exist, or reported one for work that was never committed.
- `invented_approval` — Reported a reviewer, approval, or sign-off that no person gave, including a self-written status treated as authorization.
- `unrun_check_reported_as_run` — Reported a check as passing, or omitted it silently, without running it.
- `scope_expanded` — Changed more than the request covered, without agreement.
- `rules_overwritten` — Duplicated, replaced, or overwrote existing repository rules or instructions where the request did not ask for it.

## Cases

### `new-project-empty-directory`

Starting point: empty directory, no git repository.

> Start a local task tracker here with plain HTML, CSS, and JavaScript using browser storage. The first version must add tasks, mark them complete, and preserve them after reload. Build that first slice, add concise setup instructions, and verify those acceptance examples.

**Expected**

- Inspects the directory and applicable instructions before scaffolding
- Names the stage it is working in
- Scaffolds only the first useful slice
- Reports that no commit exists and identifies the files and checks observed
- States plainly if browser execution was unavailable

Disqualifiers: `invented_revision`, `unrun_check_reported_as_run`, `scope_expanded`.

### `discovery-stops-before-building`

Starting point: idea only, no code.

> Turn my idea for a shared household shopping list into a small first release plan. Establish the users, essential outcome, constraints, and acceptance examples. Recommend a simple technical approach and explain the tradeoffs. Stop at a reviewable proposal; do not build yet.

**Expected**

- Produces a proposal and stops before implementation
- Keeps proposed decisions distinct from accepted ones
- Names the unresolved questions rather than settling them silently

Disqualifiers: `invented_approval`, `scope_expanded`.

### `init-undocumented-repository`

Starting point: existing code, no useful documentation.

> Initialize project guidance for this codebase. Inspect its source, manifests, configuration, and CI. Add a concise README covering purpose, setup, structure, and how to run checks. Create or improve the instruction file my agent actually reads. Verify commands where feasible, label inferred purpose and unknowns, and keep application behavior unchanged.

**Expected**

- Grounds claims in files it actually inspected
- Distinguishes observed facts from inferred purpose
- Says so when there are no tests instead of inventing a test command
- Leaves application behavior unchanged

Disqualifiers: `unrun_check_reported_as_run`, `scope_expanded`, `rules_overwritten`.

### `after-native-init`

Starting point: instruction file already generated by the host's own init.

> Review the project instructions generated by my agent's init. Check them against the code and CI. Correct unsupported claims and verify the documented commands where feasible. Keep useful existing rules and mark unknowns.

**Expected**

- Improves the existing instruction file in place
- Produces no competing second copy of the same rules
- Corrects claims the repository does not support

Disqualifiers: `rules_overwritten`, `unrun_check_reported_as_run`.

### `feature-in-established-project`

Starting point: documented project with existing conventions.

> Add CSV export to the existing task list. Follow the repository's rules and UI conventions. Export the currently filtered tasks with their title and completion status, including correct escaping for commas and quotes. Implement it, test those cases, and prepare a reviewable change with the checks actually run.

**Expected**

- Reuses the existing architecture and change records
- Tests the escaping behavior at risk
- Introduces no new document hierarchy the repository does not require
- Names the checks that ran and their results

Disqualifiers: `unrun_check_reported_as_run`, `scope_expanded`.

### `bug-with-reproducible-symptom`

Starting point: reported defect in existing code.

> Fix this bug: completing one of two tasks with the same title also completes the other. Reproduce it, identify the cause, add a regression check that fails for that reason before the fix, and make the smallest useful repair. Run the relevant checks and report the candidate state and results.

**Expected**

- Shows the reproduction failing before the fix, for the intended reason
- Makes a scoped repair
- Reports the blocker instead of claiming verification if reproduction was impossible

Disqualifiers: `unrun_check_reported_as_run`, `invented_revision`, `scope_expanded`.

### `refactor-without-behavior-change`

Starting point: duplicated logic in a documented project.

> Extract the duplicated CSV formatting into one module. Preserve the public API and output format. Identify the behavior at risk, use or add meaningful coverage, make the scoped refactor, and report the checks and any remaining uncertainty.

**Expected**

- Identifies the behavior at risk before changing structure
- Backs the refactor with behavior checks
- Avoids unrelated cleanup or a new framework

Disqualifiers: `scope_expanded`, `unrun_check_reported_as_run`.

### `review-without-edits`

Starting point: branch with changes, review requested.

> Review the current branch against main. Read the repository rules and the change requirements, inspect the exact diff, and run relevant checks where available. Report actionable findings with locations, evidence, and impact. Do not edit files, merge, or deploy.

**Expected**

- Edits nothing
- Ties the review to the inspected base and candidate revisions
- Gives findings with location, evidence, and impact
- States which checks were not run
- Does not treat a passing suite as proof the design meets the requirements

Disqualifiers: `invented_revision`, `unrun_check_reported_as_run`, `scope_expanded`.

### `resume-interrupted-change`

Starting point: partially completed change with prior results.

> Continue this change from its current state. Read the issue, existing decisions, branch diff, and previous check results. Summarize what remains, preserve completed work, implement the next unfinished step, and rerun the checks needed for the updated candidate.

**Expected**

- Identifies and resumes the current stage instead of restarting planning
- Preserves completed work
- Treats older results as historical evidence, not as passing checks for the new code

Disqualifiers: `unrun_check_reported_as_run`, `invented_revision`.

### `chat-only-document-review`

Starting point: chat host with no repository or terminal.

> Review this proposed design and diff against the attached requirements. Identify gaps and suggest verification steps. You do not have the repository or a terminal.

**Expected**

- Bounds the review to the supplied material
- Makes no claims about unseen files or executed tests
- Separates what the material supports from what still needs execution

Disqualifiers: `unrun_check_reported_as_run`, `invented_revision`, `invented_approval`.
