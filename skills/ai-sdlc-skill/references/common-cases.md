# Common cases and example prompts

Install and select the skill using your [host's supported route](https://github.com/Andreasniss/ai-sdlc-skill/blob/main/INSTALLATION.md), then give it a task in ordinary language. These examples describe intended behavior, not completed runtime evaluations. Replace the sample requirements with your own. The agent should apply existing authorization and ask only about material gaps that prevent responsible progress.

## New project in an empty directory

> Use AI SDLC Skill to start a local task tracker in this directory. Use plain HTML, CSS, and JavaScript with browser storage. The first version must add tasks, mark them complete, and preserve them after reload. Build that first slice, add concise setup instructions, and verify those acceptance examples. Keep it local for now.

Expect the agent to inspect the directory and applicable instructions first, establish the small scope, scaffold the app, and check the requested behavior. It should report limitations if browser execution is unavailable. No existing Git history or documentation is required. Before the first commit, the report should say that no commit exists and identify the files checked; it must not invent a revision. Local scaffolding does not imply a remote repository or deployment.

If you have only an idea, use a discovery task first:

> Use AI SDLC Skill to turn my idea for a shared household shopping list into a small first release plan. Help me establish the users, essential outcome, constraints, and acceptance examples. Recommend a simple technical approach and explain the important tradeoffs. Stop at a reviewable proposal; do not build yet.

Expect proposed choices and unresolved questions, without claiming you accepted decisions you have not made.

## Existing code with no useful documentation

> Use AI SDLC Skill to initialize project guidance for this codebase. Inspect its source, manifests, configuration, and CI. Add a concise README covering purpose, setup, structure, and how to run checks. Create or improve the instruction file my current agent actually reads. Verify commands where feasible, label inferred purpose and unknowns, and keep application behavior unchanged.

Expect facts grounded in the repository, small documentation changes, and explicit gaps. If there are no tests, the agent should say so rather than invent a passing test command. This task does not authorize adding a test framework, refactoring code, or replacing existing rules merely to make initialization look complete.

## After the agent's native `/init`

Native initialization belongs to the coding agent. For example, [Claude Code documents `/init`](https://code.claude.com/docs/en/memory#set-up-a-project-claudemd) as a way to generate starting project instructions in `CLAUDE.md`. Other hosts may use different commands or files. AI SDLC Skill adds no universal `/init` command. You can use a host's initialization first, or ask the skill to establish context directly with the previous prompt. Neither requires running both.

> Use AI SDLC Skill to review the project instructions generated by my agent's init. Check them against the code and CI. Correct unsupported claims and verify the documented commands where feasible. Keep useful existing rules, mark unknowns, and add only the delivery guidance this project needs. Keep application behavior unchanged.

Expect an improvement to the existing instructions, with no competing copy of the same rules. An agent's initialization is also separate from `git init`, which creates Git metadata; check whether this directory already belongs to a repository before considering that operation.

## Feature in an established project

> Use AI SDLC Skill to add CSV export to the existing task list. Follow the repository's rules and UI conventions. Export the currently filtered tasks with their title and completion status, including correct escaping for commas and quotes. Implement the feature, test those cases, and prepare a reviewable change with the checks actually run.

Expect the agent to reuse the current architecture and change records, explain material choices, and test export behavior. A new document hierarchy is unnecessary unless the repository requires one.

## Bug with a reproducible symptom

> Use AI SDLC Skill to fix this bug: completing one of two tasks with the same title also completes the other. Reproduce it, identify the cause, add a regression check that fails for that reason before the fix, and make the smallest useful repair. Run the relevant checks and report the candidate state and results.

Expect evidence for the failure and repair. If reproduction is blocked by missing data or tools, the agent should report the blocker rather than claim the bug is verified.

## Refactor without changing behavior

> Use AI SDLC Skill to extract the duplicated CSV formatting into one module. Preserve the public API and output format. Identify the behavior at risk, use or add meaningful coverage, make the scoped refactor, and report the checks and any remaining uncertainty.

Expect a scoped structural change backed by behavior checks, without unrelated cleanup or a new framework.

## Review without edits

> Use AI SDLC Skill to review the current branch against main. Read the repository rules and the change requirements, inspect the exact diff, and run relevant checks where available. Report actionable findings with locations, evidence, and impact. Do not edit files, merge, or deploy.

Expect a review tied to the inspected base and candidate, including uncommitted changes if present, and a clear account of unrun checks. A passing test suite alone does not establish that the design meets the requirements.

## Resume an interrupted change

> Use AI SDLC Skill to continue this change from its current state. Read the issue, existing decisions, branch diff, and previous check results. Summarize what remains, preserve completed work, implement the next unfinished step, and rerun the checks needed for the updated candidate.

Expect the agent to pick up the current stage rather than restart planning. Older results remain historical evidence, not passing checks for newly changed code.

## Planning or review in a chat-only environment

> Use the attached AI SDLC Skill instructions to review this proposed design and diff against the attached requirements. Identify gaps and suggest verification steps. You do not have the repository or a terminal, so distinguish what the supplied material supports from what still needs execution.

Expect a bounded document review, with no claims about unseen files, executed tests, or an installed skill. Attach the relevant skill files when the host cannot load them itself.
